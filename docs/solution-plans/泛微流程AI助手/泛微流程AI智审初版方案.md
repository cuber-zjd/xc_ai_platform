# 泛微流程 AI 智审初版方案

## 目标

在泛微 E9 流程审批节点引入 AI 预审能力，让审批人打开待办前或审批时看到风险提示、缺失材料、建议结论和建议审批意见，减少无谓退回和沟通成本。

## 初版边界

- AI 只做预审建议，不直接保存、提交、审批、退回或删除流程。
- 审批页 ecode 只负责展示智审入口和传递当前表单上下文。
- Java Action 只负责在节点流转时调用平台接口生成智审记录，默认不阻断流程。
- 平台保存每次预审的表单快照、规则快照和模型结果，便于复盘与后续替审评估。

## 平台入口

- 智审展示页：`/weaver/assistant/review`
- 智审规则配置页：`/weaver/assistant/review-config`
- 智审接口：`POST /api/v1/weaver/ai-assistant/review/precheck`
- 最近智审记录：`GET /api/v1/weaver/ai-assistant/review/latest`
- 智审规则维护：`/api/v1/weaver/ai-assistant/review-rules`

## 数据表

- `weaver_ai_review_rule`：按 `env + workflow_id + node_id + reviewer_user_id` 维护智审规则。
- `weaver_ai_review_record`：保存每次智审结果，包括风险等级、建议结论、检查项、缺失材料、关注点和建议审批意见。

## 泛微侧代码

- 审批页 ecode：`docs/solution-plans/泛微流程AI助手/ecode/泛微流程AI智审-审批页ecode脚本.js`
- 规则配置页 ecode：`docs/solution-plans/泛微流程AI助手/ecode/泛微流程AI智审-规则配置页ecode脚本.js`
- Java Action：`docs/solution-plans/泛微流程AI助手/java/WeaverAiReviewAction.java`

## 推荐落地方式

1. 先在测试流程审批页加入“AI智审”悬浮入口。
2. 在流程路径设置页加入“AI智审规则”页签，配置流程通用规则。
3. 将 `WeaverAiReviewAction` 挂到测试流程节点后附加操作，提交后自动生成预审记录。
4. 审批人打开待办时查看 AI 智审建议，人工决定审批动作。
5. 积累一段时间后，统计低风险且审批人采纳率高的场景，再评估 `autoReviewMode=auto` 的替审能力。

## 后续替审要求

后续如果启用 AI 替审，必须满足：

- 审批人显式授权。
- 只允许白名单流程、白名单节点和低风险条件。
- 每次替审保存规则版本、模型结果、表单快照和操作结果。
- 高风险、材料缺失、置信度不足或模型异常时必须转人工。
- 不允许 AI 自行越过泛微权限、跳过必审节点或执行任意脚本。

## 建模数据与发票明细核验（2026-07-21）

智审规则支持启用“核对采购对账单与发票明细”只读工具。该能力不录制用户操作，也不模拟页面点击，而是从泛微建模元数据反向解析数据结构：

1. 根据规则中的 `customId` 查询 `mode_customsearch`，取得建模应用的 `FORMID`。
2. 通过 `workflow_bill`、`workflow_billfield` 和中文字段标签解析建模主表、对账单号字段、采购物料明细表及金额和税率字段。
3. 优先从当前流程上下文读取对账单号和发票浏览框的记录 ID/显示值。
4. 审批页未渲染标准 `field*` 输入框、浏览框仅存在 React 组件或 ecode 未采集到字段时，平台根据 `workflowId + requestId` 反查 `workflow_base`、`workflow_bill`、`workflow_billfield`，定位当前流程表单主表和明细表，再按中文字段标签读取关联值。上下文缺字段只代表采集缺失，不得作为业务字段为空的依据。
5. 对账数据按主表 ID 读取采购物料明细；发票通过 `fnainvoiceledger.id` 和 `fnainvoiceledgerdetail.mainid` 读取发票及商品明细。
6. 对账单重复物料先按规范化商品名聚合，再与发票商品做受控近似匹配，同时核验未税金额、税率、价税合计和发票查验状态。
7. 工具结论作为确定性证据进入智审。金额、税率或商品不一致时，模型不得把检查项改写为通过，也不得自动替审；工具和上下文均无证据的数据不得由模型臆测。

当前测试场景：

- 流程：`workflowId=365`，电采供应商付款单。
- 建模查询：`customId=186`，博川采购账单查询。
- 建模主表：`uf_bscgdd`；采购物料明细表：`uf_bscgdd_dt2`。
- 发票主表：`fnainvoiceledger`；发票商品明细表：`fnainvoiceledgerdetail`。
- 测试单 `requestid=1987986` 已验证：对账单 `PR202606220088` 关联 1 张发票，价税合计一致，双方聚合后均为 21 项商品且全部匹配。
- 已补充空页面字段回归验证：当 ecode 传入 `fields={}` 时，平台仍可从流程数据库读取对账单号和发票浏览框 ID，并得到相同核验结果。
- 智审结果会保存结构化 `comparisonTables`：包含对账单号、发票号码、双方价税合计，以及逐项商品名称、未税金额、税率、匹配度和核对状态。审批页默认展开摘要和明细对比表，异常项单独高亮，金额差在规则容差内时按一致处理并保留原始双方金额。
- 明细对比表采用内部横向和纵向滚动，避免 20 项以上明细撑高或撑宽整个智审侧栏；最近智审记录重新打开时仍可读取已经保存的对比数据。
- 明细对比以对账单为主体，按对账单明细原始顺序展示“序号、对账物料、发票商品”；同一物料存在多条对账明细时聚合核验并保留全部原始序号，发票侧未匹配项排列在对账明细之后，方便业务人员回到泛微明细快速定位。

平台规则页由业务人员勾选工具并填写采购账单查询 ID，不需要填写 SQL。查询仅允许读取由泛微元数据解析出的合法表名和字段名，单次明细读取限制为 500 行，执行证据会随智审快照保存。

本次能力全部位于平台前后端，审批页 ecode 无需修改。

## 动态形象交互

- 智审入口与填表助手复用同一套动态助手形象。
- 悬浮态保持轻量呼吸、漂浮和眨眼；点击后连续展开为智审面板，关闭时反向收回。
- 智审执行中切换为思考状态，低风险完成后切换为成功状态，其他结果保持智审状态徽标。
