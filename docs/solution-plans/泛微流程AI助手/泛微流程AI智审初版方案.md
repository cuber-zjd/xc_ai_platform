# 泛微流程 AI 智审初版方案

## 目标

在泛微 E9 流程审批节点引入 AI 预审能力，让审批人打开待办前或审批时看到风险提示、缺失材料、建议结论和建议审批意见，减少无谓退回和沟通成本。

## 初版边界

- AI 只做预审建议，不直接保存、提交、审批、退回或删除流程。
- 审批页 ecode 只负责展示智审入口和传递当前表单上下文。
- 平台定时扫描器每分钟读取已开启自动预审的节点待办并生成智审记录；Java Action 仅作为“提交后立即触发”的可选补充。
- 平台保存每次预审的表单快照、规则快照和模型结果，便于复盘与后续替审评估。

## 平台入口

- 智审展示页：`/weaver/assistant/review`
- 智审规则配置页：`/weaver/assistant/review-config`
- 智审接口：`POST /api/v1/weaver/ai-assistant/review/precheck`
- 最近智审记录：`GET /api/v1/weaver/ai-assistant/review/latest`
- 智审规则维护：`/api/v1/weaver/ai-assistant/review-rules`
- 节点启用范围：`GET/PUT /ai-api/v1/weaver/ai-assistant/review/node-configs`
- 节点生效状态：`GET /ai-api/v1/weaver/ai-assistant/review/node-status`
- 测试审批：`POST /ai-api/v1/weaver/ai-assistant/review/test`

## 数据表

- `weaver_ai_review_rule`：按 `env + workflow_id + node_id + reviewer_user_id` 维护智审规则。
- `weaver_ai_review_node_config`：按 `env + workflow_id + node_id` 唯一维护节点总开关、审批页入口和自动预审开关；未配置默认关闭。
- `weaver_ai_review_record`：保存每次智审结果，包括风险等级、建议结论、检查项、缺失材料、关注点和建议审批意见。
- `weaver_ai_review_test_record`：独立保存配置页测试审批的表单快照、规则快照、来源节点和模型结果，不进入正式智审记录链路。
- `weaver_ai_review_scan_task`：按环境、流程、请求、节点、审批人和泛微待办记录唯一留存扫描任务，负责幂等、失败重试和智审记录关联。

## 测试审批（2026-08-03）

- 入口位于“流程 AI 智审控制”页右上角，点击“测试审批”后输入当前流程中的 `requestId`。
- 平台校验该请求确实属于当前配置流程，随后从所选环境的泛微数据库读取流程主表、全部明细表和规则声明的只读证据。
- 测试时忽略请求当前所在节点、节点启用开关和自动预审开关，并加载当前流程全部启用的智审规则；真实当前节点仅作为来源信息展示和留档。
- 结果弹窗直接复用审批侧栏的风险卡、检查项和明细对比表，避免测试页与审批人看到的效果不一致。
- 测试结果只写入 `weaver_ai_review_test_record`，不会被“最近一次智审”读取，不进入正式审计统计，也不会触发审批、退回、提交或自动替审。
- `requestId` 不存在、属于其他流程、流程主表无数据或数据库环境未配置时直接给出明确错误，不调用模型。
- 本功能完全位于平台前后端，现有智审配置页 ecode 无需修改；平台部署更新后原入口自动出现“测试审批”按钮。

## 推荐落地方式

1. 在流程路径设置页加入“AI智审规则”页签，从中文节点列表中只启用需要智审的节点。
2. 为启用节点配置流程通用、节点级或审批人个人规则；规则存在不等于节点启用。
3. 打开节点的“自动预审”后，平台扫描器会每分钟发现该节点当前待办并预审，不需要逐流程、逐节点挂 Action；只有必须在提交瞬间完成时才选配 `WeaverAiReviewAction`。
4. 智审完成后，审批人进入待办页面会在悬浮图标附近收到风险等级和摘要提醒，点击提醒打开完整智审详情。
5. 积累一段时间后，统计低风险且审批人采纳率高的场景，再评估 `autoReviewMode=auto` 的替审能力。

## 节点启用机制（2026-08-03）

- 节点启用范围是智审的总开关，按环境隔离，因此测试与正式系统的流程 ID、节点 ID 不需要保持一致。
- 配置页从当前环境的泛微数据库读取流程中文名称和节点中文名称，管理员直接按名称选择。
- ecode 仅在当前节点 `enabled=true` 且 `showEntry=true` 时显示 AI 智审图标；未配置、关闭、节点无法识别或状态接口失败时均隐藏。
- 手动点击“立即智审”要求节点总开关开启；`submit/action` 自动调用还要求 `automaticReviewEnabled=true`。
- 后端在证据查询和模型调用之前执行校验，避免关闭节点仍产生数据库查询、模型费用或智审记录。
- 后端生命周期会启动一分钟扫描器，只读取 `enabled=true`、`automaticReviewEnabled=true` 且状态有效的节点。扫描器从 `workflow_currentoperator` 发现当前审批人待办，同一条待办只执行一次；流程退回后再次进入相同节点时，新的待办记录会重新预审。
- 单轮扫描默认最多处理 10 条待办、并发 2 条、失败最多重试 3 次。状态和手工扫描接口分别为 `GET /review/scheduler/status` 与 `POST /review/scheduler/run-once`。
- 候选发现按泛微待办记录倒序读取，并扩大候选窗口后逐条执行平台幂等领取；已完成的旧待办只能计为跳过，不得占用本轮真实执行名额，避免新待办被长期饿死。

## 后续替审要求

后续如果启用 AI 替审，必须满足：

- 审批人显式授权。
- 只允许白名单流程、白名单节点和低风险条件。
- 每次替审保存规则版本、模型结果、表单快照和操作结果。
- 高风险、材料缺失、置信度不足或模型异常时必须转人工。
- 不允许 AI 自行越过泛微权限、跳过必审节点或执行任意脚本。

## 建模数据与发票明细核验（2026-07-21）

智审规则支持启用“核对采购对账单与发票明细”只读工具。该能力不录制用户操作，也不模拟页面点击，而是从泛微建模元数据反向解析数据结构：

1. 根据规则中的 `customId` 查询 `mode_customsearch`，取得建模应用的 `FORMID`。
2. 通过 `workflow_bill`、`workflow_billfield` 和中文字段标签解析建模主表、对账单号字段、采购物料明细表及金额和税率字段。
3. 优先从当前流程上下文读取对账单号和发票浏览框的记录 ID/显示值。
4. 审批页未渲染标准 `field*` 输入框、浏览框仅存在 React 组件或 ecode 未采集到字段时，平台根据 `workflowId + requestId` 反查 `workflow_base`、`workflow_bill`、`workflow_billfield`，定位当前流程表单主表和明细表，再按中文字段标签读取关联值。上下文缺字段只代表采集缺失，不得作为业务字段为空的依据。
5. 对账数据按主表 ID 读取采购物料明细；发票通过 `fnainvoiceledger.id` 和 `fnainvoiceledgerdetail.mainid` 读取发票及商品明细。
6. 对账单重复物料先按规范化商品名聚合，再与发票商品做受控近似匹配，同时核验未税金额、税率、价税合计和发票查验状态。
7. 工具结论作为确定性证据进入智审。金额、税率或商品不一致时，模型不得把检查项改写为通过，也不得自动替审；工具和上下文均无证据的数据不得由模型臆测。

当前测试场景：

- 流程：`workflowId=365`，电采供应商付款单。
- 建模查询：`customId=186`，博川采购账单查询。
- 建模主表：`uf_bscgdd`；采购物料明细表：`uf_bscgdd_dt2`。
- 发票主表：`fnainvoiceledger`；发票商品明细表：`fnainvoiceledgerdetail`。
- 测试单 `requestid=1987986` 已验证：对账单 `PR202606220088` 关联 1 张发票，价税合计一致，双方聚合后均为 21 项商品且全部匹配。
- 已补充空页面字段回归验证：当 ecode 传入 `fields={}` 时，平台仍可从流程数据库读取对账单号和发票浏览框 ID，并得到相同核验结果。
- 智审结果会保存结构化 `comparisonTables`：包含对账单号、发票号码、双方价税合计，以及逐项商品、单位、数量、未税金额、税率、名称匹配度和综合核对状态。对账单“采购物料描述”作为完整物料名称，发票“商品名称 + 规格型号”合并后与其综合匹配，不再单独判定规格型号。
- “名称匹配度”只表示上述完整名称组合后的相似程度；综合结果统一为“一致、待核对、异常”。名称匹配成功后再核对数量、未税金额和税率，任一已有维度明确不一致即为异常，一侧缺少数量时标记为待核对。对账单位暂只展示、不参与异常判定。
- 发票数量兼容泛微台账的 `unitNumber` 与 `unitNumber2` 字段，优先读取 `unitNumber`，为空时回退到 `unitNumber2`。
- 商品名称采用混合匹配：归一化后的完整名称完全一致时由程序直接确认；其余复杂名称按批次交给 `WEAVER_AI_MODEL_NAME` 指定模型或 `complex-reasoning` 能力模型做语义匹配。模型需要综合商品类别、用途、材质、行业同义词、颜色、型号、容量和包装信息，数量、金额、税率仅用于候选消歧，不能把明显不同商品强行配对。
- 语义匹配批次会向模型提供待匹配发票项和完整对账物料目录，避免字面差异过大时被字符串候选召回提前漏掉；模型只能返回目录中的编号，并必须给出置信度和简短依据。后端再次校验编号范围、最低置信度和发票/对账行一对一约束。模型不确定时保留为未匹配，模型调用失败时只回退到高置信字符串匹配。
- 大批量明细按每批 30 个发票商品受控并发调用，默认最多 3 个批次同时执行；全部结果返回后按置信度做全局一对一冲突消解。最终比较表记录 `exact_normalized`、`ai_semantic`、`fallback_fuzzy` 或 `unmatched` 匹配来源，便于审计。
- 审批页默认按“异常优先”展示，可切换“对账顺序”或“仅看异常”。异常行及具体不一致的数量、金额、税率等单元格标红，金额差在规则容差内时按一致处理并保留原始双方金额。
- 明细对比表采用内部横向和纵向滚动，避免 20 项以上明细撑高或撑宽整个智审侧栏；最近智审记录重新打开时仍可读取已经保存的对比数据。
- 明细对比以对账单为主体，按对账单明细原始顺序展示“序号、对账物料、发票商品”；同一物料存在多条对账明细时聚合核验并保留全部原始序号，发票侧未匹配项排列在对账明细之后，方便业务人员回到泛微明细快速定位。
- “发票商品与对账物料”检查项会用 ①②③… 对未匹配或维度不一致的项目编号，并包含对账单原始序号。

平台规则页由业务人员勾选工具并填写采购账单查询 ID，不需要填写 SQL。查询仅允许读取由泛微元数据解析出的合法表名和字段名，单次明细读取限制为 500 行，执行证据会随智审快照保存。

本次明细核验能力位于平台前后端；可拖拽面板宽度需要整段替换审批页 ecode 脚本。

## 动态形象交互

- 智审入口与填表助手复用同一套动态助手形象。
- 悬浮态保持轻量呼吸、漂浮和眨眼；点击后连续展开为智审面板，关闭时反向收回。
- 智审执行中切换为思考状态，低风险完成后切换为成功状态，其他结果保持智审状态徽标。

# 明细比对状态口径（2026-08-03）

- 发票商品无法与对账物料建立可信关联时判定为“异常”，整行使用红色背景。
- 已建立关联但名称匹配度不足 100% 时判定为“待核对”，整行使用黄色背景，并在名称两侧展示“名称待核对”。
- 名称完全一致后，继续比较单位、数量、未税金额和税率；任一项明确不一致时判定为“异常”，缺少一侧数据时判定为“待核对”。
- 对账单单位优先按字段标签读取，同时兼容明细字段名 `dw`。
- 智审面板支持拖拽至接近浏览器全屏宽度，用户调整后的宽度继续保存在浏览器本地。
