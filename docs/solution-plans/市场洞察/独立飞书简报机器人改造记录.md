# 独立飞书简报机器人改造记录

## 一、功能定位

“飞书简报”是独立于“报告中心”的管理员功能，入口为 `/insight/feishu-briefs`。

- 报告中心：用户按需研究、选素材、生成和导出通用报告。
- 飞书简报：后台按日报、周报或月报计划，从正式情报中取材，严格按领导确定的版式创建飞书云文档并推送。
- 简报文档使用独立飞书应用的机器人身份创建，不使用配置计划的管理员身份。
- 计划、执行记录、云文档地址、推送结果和失败原因单独保存，不写入普通报告列表。

## 二、固定版式

生成内容严格沿用领导确认的健源、御馨报告格式，固定为：

1. 文档标题：`公司简称｜YYYY年M月第X周信息简报`，周次按周一至周日确定。
2. 管理层情报简报、报告周期、生成时间、适用公司、数据来源和原始候选数量。
3. `一、总览`，使用固定总览句式。
4. 政策、竞对、客户、技术、原料五类连续分析正文。
5. `二、重点情报导读`，固定 7 条；标题直接链接原文，下一行仅放分类和事件标签，再写一段完整事实。

领导定稿的版式骨架和代表性写作样例直接放入模型提示词。模型不得自行增加“业务启示、机会、风险、行动建议、时间、内容、来源”等字段或章节。系统会检查章节顺序、导读数量、标题链接和来源链接；检查不通过时最多自动修复两轮，仍不通过则记录失败，不发布格式不合格的文档。

分类正文采用“事件归并后成文”，不采用“来源逐条拼接”：

- 每段先概括共同变化，再融合 2 至 4 条材料作为支撑。
- 超链接挂在事件、项目、产品或经营动作短语上，不显示裸网址，不直接复制冗长的文章原标题。
- 同一事件只出现一次，弱相关材料不得用于凑数。
- 单段过长、正文裸网址、冗长原标题作为链接文字会触发自动修复。
- 多数链接必须位于句首或句子前 30 个汉字内，直接充当事件主语、宾语或谓语，禁止在完整事实后补挂标题链接。
- 来源 URL 明确包含的年份与情报发布时间冲突时，不进入简报素材；明显没有本周期新进展的历史旧闻也要求舍弃。
- 重点情报导读标题需要重新概括事件，正文保留主体、动作、数字和背景。
- 头部周期与公司信息采用居中排版，元信息区与正文之间使用真实分隔线；重点情报导读的一级分类和事件标签由代码写入不同底色，不依赖模型输出样式。

生成前增加独立选材编辑环节：

- 先按所属公司的真实业务边界判断相关性。健源重点关注玉米精深加工、果葡糖浆、麦芽糖浆、功能糖和糖醇；御馨重点关注大豆精深加工、植物蛋白、蛋白粉、豆粕及其客户应用。
- 按相关性、时效性、证据具体度、来源可信度和管理价值评分，低于 70 分不进入写作上下文。
- 榜单、加盟软文、商业供货广告、旧闻、包装外观专利、通用设备专利和需要多层推测才能关联业务的材料不用于凑数。
- 选中与排除结果及理由写入执行记录 `output_payload.material_selection`，便于追溯。

初稿通过固定格式检查后，再执行独立业务编辑终审，检查弱相关事实、夸大推导、分类错误、旧闻和高价值素材遗漏。终审发现问题时只允许基于已选正式情报定向修订，最多执行两轮“终审—修订—复审”；每轮修订后均重新执行确定性格式和链接白名单检查，两轮后仍不合格则终止发布。

## 三、计划配置

计划配置按三个区块维护：

1. 基础计划：所属公司、日报/周报/月报、执行日、执行时间、素材周期、素材数量、月报生成策略和启停状态。
2. 提示词：页面可展开查看领导固定模板和写作样例；用户只能在“本计划补充要求”中追加本计划关注重点。
3. 分批推送：上午审阅组和下午正式接收组分别从系统人员选择弹窗维护，已选人员以卡片展示；下午发送时间可单独设置。

素材周期与生成周期彼此独立。日报、周报或月报只决定计划何时执行，`material_days` 决定每次从正式情报中向前取多少天，页面预设近 1、3、7、15、30、31 天。月报支持单模型整稿、分章节并行、多智能体研究和多策略择优，详细口径见《飞书月报多智能体生成与审校策略》。

周报只生成一篇云文档。生成完成后，系统先向上午审阅组发送“打开并审阅”卡片，并通过飞书云文档协作者接口授予编辑权限；下午到点后只发送同一文档链接，不重新生成、不覆盖上午修改。两批推送人员和结果均随执行记录保存，后端重启后仍可继续处理待发送的下午批次。

推送使用飞书 `interactive` 消息卡片。计划未选择任何接收人时只创建云文档，不发送消息；只配置下午接收人时，文档生成后进入待发送状态。

## 四、环境变量

在 `backend/.env` 中补充：

```env
INSIGHT_FEISHU_BRIEF_ENABLED=true
INSIGHT_FEISHU_BRIEF_APP_ID=
INSIGHT_FEISHU_BRIEF_APP_SECRET=
INSIGHT_FEISHU_BRIEF_FOLDER_TOKEN=
INSIGHT_FEISHU_BRIEF_BOT_NAME=市场洞察报告机器人
INSIGHT_FEISHU_BRIEF_DEFAULT_RECIPIENTS_JSON=[]
INSIGHT_FEISHU_BRIEF_TIMEOUT_SECONDS=30
INSIGHT_FEISHU_BRIEF_MAX_MATERIALS=200
```

接收人示例：

```json
[{"receive_id_type":"open_id","receive_id":"ou_xxx","name":"张三"}]
```

飞书应用需具备创建云文档、编辑云文档和发送消息权限；目标文件夹必须向该应用开放写入权限。未完成配置时可以维护计划，但系统不会执行发布。

## 五、执行链路

`到期计划 -> 查询对应公司周期内正式情报 -> 确定性质量拦截 -> AI 选材排序 -> 事实归并 -> 领导定稿模板生成 -> 格式校验 -> 最多两轮业务审校与修订 -> 确定性排版 -> 机器人创建云文档 -> 上午审阅组编辑 -> 下午发送同一文档 -> 保存两批推送记录`

飞书简报使用独立的到点调度任务，按数据库中的 `next_run_time` 和下午待发送时间唤醒，最长每 60 秒校准一次计划变更。它不依赖每日情报采集任务的凌晨扫描，因此周二 09:00 的计划会在周二 09:00 执行，不会拖到下一次凌晨采集。

日报取最近 1 天正式情报，周报取最近 7 天正式情报；定时月报取上一个完整自然月，手工运行可显式指定自然月起止日期。所属公司沿用情报中心同步飞书时的公司归属判断，避免另建一套口径。

业务审校用于修正弱相关、夸大推断、分类错误和遗漏重点，不允许把已由原文日期、正文和来源确认的事实改成模型猜测。两轮审校后不再因新的主观编辑偏好反复重写；日期冲突、链接越界、固定章节缺失等确定性问题仍会阻止发布。

系统同时对“将显著增加采购需求”“直接指向新增采购”“必然带动销量”以及无来源支撑的业绩归因做确定性拦截。原文未披露采购量、采购计划或经营结果时，只允许写客观动作，或使用“可能影响”“值得关注”等有证据边界的表达。

重点导读标题另设管理语言检查：只保留材料明确披露的主体和动作，禁止“死磕、引爆、撬动、倒逼”等媒体化词语，也禁止把潜在影响压缩成“收缩外采、致战略延缓”等确定结论。

领导定稿只呈现事实，因此校验不只检查显式的“建议”栏目，还会拦截“香驰需、我司应、需关注、需警惕、需评估”等隐藏在正文里的行动建议，以及未经材料确认的未来采购需求增减结论。

业务审校改稿后会再次执行同一套确定性检查；若改稿引入格式、事实边界或建议性表达问题，系统会使用剩余修订轮次继续纠正，最终仍未通过才终止发布并记录失败原因。

为避免模型连续修订仍保留固定坏句式，成文后还会执行确定性编辑清洗：规范媒体化导读标题；能够安全改写的强需求因果降为审慎表达；仍命中未经确认强因果或隐性行动建议的完整句直接删除。清洗后仍须通过统一校验，不能绕过质量门槛。

## 六、接口

- `GET /ai-api/v1/insight/feishu-briefs/options`
- `GET/POST /ai-api/v1/insight/feishu-briefs/plans`
- `PUT/DELETE /ai-api/v1/insight/feishu-briefs/plans/{id}`
- `POST /ai-api/v1/insight/feishu-briefs/plans/{id}/run`
- `GET /ai-api/v1/insight/feishu-briefs/runs`
- `POST /ai-api/v1/insight/feishu-briefs/run-due`
- `POST /ai-api/v1/insight/feishu-briefs/run-due-deliveries`

以上接口仅管理员可访问。正式调度器每轮会扫描到期简报计划，未启用或配置不完整时直接跳过。
