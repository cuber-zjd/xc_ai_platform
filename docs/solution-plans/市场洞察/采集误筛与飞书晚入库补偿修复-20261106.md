# 采集误筛与飞书晚入库补偿修复

## 问题与证据

- 2026-11-06 凌晨飞书同步新增 17 条、更新 1 条，但当天截至排查时已新增 30 条正式情报。两者不是同一统计口径；旧同步按文章发布日期筛选，会漏掉晚入库的旧文章，也不覆盖夜间同步之后的新记录。
- 近期正文补偿反复出现 `MissingGreenlet`。循环预加载多条 ORM 对象，首条失败回滚使整个会话对象过期，下一条读取属性触发不被允许的隐式异步数据库访问。
- 企业档案存在 `Archer Daniels Midland (ADM)— 美国` 这样的简称，完整字符串匹配不识别单独 `ADM`；益海嘉里两条公司档案都没有明确的“金龙鱼”别名。此类应修复匹配，不应将所有未归属搜索结果无条件放行。

## 已实施代码

1. 匹配复用企业全名、简称与配置别名；仅拆出括号中已明确写出的英文缩写，保留英文词边界，避免 `ADM` 命中 `admin`。不自动猜测品牌关系。
2. 正文补偿只预存 ID，每条显式重读；失败后下一条继续。正文有效性再次校验；已取到正文但后续评审异常时单独记评审错误，不将成功正文覆盖为抓取失败。
3. 定时飞书同步改为全库有效 ID 对账：远端没有的补齐，已有记录按入库/更新时间与远端同步水位更新。文章发布日期不影响自动同步。手动日期范围和可见性过滤保持原语义。
4. 分页读取无 2000 条静默截断；手动与定时同步共用数据库会话锁，避免同时查缺导致重复新增；失败不更新该记录水位，下一次仍会查缺补漏。同步使用本轮读取前时点，保留五分钟重叠。
5. 新增受控回放脚本，默认只读；显式参数分别启用别名修复、有限补录、正文补偿与飞书同步。复用已付费搜索检查点，不绕过原日期、正文、AI 评审及权限归属。不生成报告、不发送卡片。

## 边界

- 搜索命中数、正文成功数、候选数、正式情报数、飞书新增数必须分别统计。匹配恢复不意味着一定是值得采用的新闻。
- 不绕过验证码、站点限流、正文门槛或日期核验。404、导航页、时间不可信的内容仍不能强行升为正式情报。
- 不修改已有报告、人工审阅内容、收件人及推送时间；不部署工作区其他未提交的报告生成改动。
- 首次全库对账会补入此前遗漏的历史有效情报，但不会删除多维表格现有记录。后续正式情报被删除/停用后远端历史行仍保留；关系表单独修改而未更新情报更新时间的情况不属于本轮增量更新承诺。
