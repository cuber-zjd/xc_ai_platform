# 飞书周报可配置多智能体流程改造

## 目标

飞书周报不再使用单次整稿生成链路，统一改为“素材准备、策划、专题研究、主笔、独立审阅、主笔修订、确定性校验、云文档、审阅推送、正式推送”。旧计划原有生成策略、业务规则、提示词补充、模板和接收人直接迁入新配置，不保留旧周报执行分支。

## 配置与调度

- 每个计划独立维护生成、审阅、正式推送的星期和时间，支持周一生成审阅、周二正式推送。
- 素材范围支持滚动天数、固定星期区间和指定日期区间。
- 单期实例可以临时覆盖时间、素材和接收人；执行后后续周期恢复常规计划。
- 时间和接收人变化立即更新本期未执行阶段；生成策略、Prompt、模板和素材配置变化只标记内容已变更，必须由用户显式原文档重生成。
- 审阅和正式推送分别持久化待发送状态，调度器先把任务置为 `sending` 再外发，服务重启不会把成功阶段重新当作待发送。

## 多智能体与调试

- 策划智能体输出研究问题、证据分布、栏目任务和信息缺口。
- 政策、竞对、客户、技术、原料五个专题研究智能体并行执行。
- 主笔使用现有领导模板、业务边界、优秀样例和用户配置成稿。
- 独立审阅智能体只把事实、相关性、重复、推断、结构、七条导读和链接问题列为阻断项；主笔按阻断项修订，最终仍需通过程序确定性检查。
- 调试运行直接接收页面未保存草稿，完整执行多智能体流程，创建 `[调试]` 云文档但绝不推送。机器人写完后按当前登录用户 `employee_id` 转移所有权，原机器人保留管理权限。

## 数据与接口

- 计划新增所有者、工作流、分角色 Prompt、Markdown 模板、素材范围和配置版本。
- 新增单期实例、计划配置版本和智能体阶段执行表；运行记录区分 `formal` 与 `debug`。
- 新增调试运行、阶段查询、配置版本、单期覆盖和取消接口；原文档重生成接口继续保留文档 ID 和权限。
